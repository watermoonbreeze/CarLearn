# Kotlin 基础

## Class 和 File

> Class 是代码的结构单位(描述对象和行为)，File是代码的组织单位(存放代码的容器)

### Class 

Kotlin的class ≈ Java 的 class

Class 类外没有任何其他方法。只有一个 Class 包裹。其他所有的形式都是 File
Class 类没有后缀，如果要Class类包层再加内容，IDE会自动添加.kt后缀，变成File类型

```kotlin
Class User {
    var name: String = ""
    fun login(){
        
    }
}
```
以上User就是Class，描述对象有什么数据，有什么行为，对象之间的关系。创建对象时 `val user = User()`

#### 什么时候使用Class

> 判断标准: 当你的东西需要"状态“或”生命周期“时，用class

1. 数据模型

```kotlin
data class User(
    val id:Int,
    val name:String
)
```
User是一个对象，有属性，状态，身份。

2. 业务对象

```kotlin
class Order{
    var items = mutableListOf<Item>()
    fun calculatePrice(){
        
    }
}
```
Order 有自己的状态

3. Repository

```kotlin
class UserRepository{
    fun getUser(){
        
    }
}
```
Repository可能：持有数据库，持有网络client，持有缓存，需要生命周期

4. ViewModel

```kotlin
class UserViewModel:ViewModel(){
    
}
```
它代表一个对象




### File

File 是Kotlin 的源码文件

`user.kt`

```kotlin
class User
fun login()
val VERSION = "1.0"
```

这里的 `login()` 没有属于任何class。Kotlin在编译时会主动生成 UserKt 这个顶层函数(Top-level function)

对比Java来说更接近 User.java ，一个源码文件，但File 比 .java 文件能力更强，放的内容类型更多

> 综上：File 是源码组织概念，Class 是运行时结构概念

> 当代码没有状态，只是提供能力时，用 File + top-level function

### 最佳实践

> 规则1： 一个核心 Class 一个File

```kotlin
// 推荐
User.kt
class User

// 避免
User.kt
class User
class Address
class Order
class Product
```

> 规则2：File名称表达里面内容

```kotlin
// 推荐
StringExtensions.kt
DateExtensions.kt
UserMapper.kt
NetworkConfig.kt

// 避免
Utils.kt
Common.kt
Helper.kt
```

> 规则3： 不要创建无意义的 Class

```kotlin
// 无状态的类直接在kt中写入方法
fun sum()

// 避免再包一层class
class MathUtils{
    fun sum()
}
```

> 规则4： 有状态-》Class，无状态-》File

1. Token管理
   因为token是对象，是有状态的对象
```kotlin

    fun save()
    fun get()

// 不推荐 
fun saveToken()
fun getToken()
```

2. JSON转换
   因为JSON转换属于工具类，没有状态
```kotlin
// 推荐

```

### 对Java开发者最重要的一点

Java: 文件=class容器
Kotlin: 文件=命名空间组织单位；class = 真正对象模型
> 所以在Kotlin中 A.kt->fun sum() B.kt->fun sum() ，不能理解成 两个类里各有一个方法，而应该理解成 两个包级函数声明。 
> 如果它们属于同一个 package，就需要避免名字冲突；如果确实需要同名，就通过**不同 package、alias import、object/class 封装**来隔离。



### 最终的判断模式

> 判断2 如果没有自己的状态，判断是不是只提供一个能力，有的话使用 File + function

## Java 到 Kotlin 的转换

一个功能: Java 是创建一个 XXUtils 类，然后static 方法；Kotlin 是创建一个 kt 文件，然后直接写函数

## 多个kt文件中有相同的方法名时如何调用

如 A.kt 中有 sum 方法，B。kt 中也有sum 方法。

1. A和B放到不同的包下，
2. A或B中的sum换个方法名称
3. 使用 import alias 声明别名 
```kotlin
import com.example.basic.sum as add
import com.example.advanced.sum as multiply

val x = add(1,2)
val y = multiply(1,4)
```
4. 使用object (Java 思维迁移)
A.kt
```kotlin
object BasicMath{
   fun sum(a:Int,b:Int) = a + b
}
```
B.kt
```kotlin
object BusinessMath {
    fun sum(a: Int, b: Int) = a * b
}
```
调用
```kotlin
BasicMath.sum(1,2)
BusinessMath.sum(1,2)
```

## Java Static 和 Kotlin top-level function 会不会导致内存占用

不会。Kotlin的File + 顶层函数本身不会介创建对象一样占用堆内存。大量顶层函数通常不会造成明显内存问题。
真正需要关注的是：代码组织、类加载数量、初始化逻辑，而不是函数数量

静态方法没有调用new 不会产生对象，如果顶层函数如果包含顶层变量，在File中会有初始化的慰问下 就会占用内存

File 的存在是为了管理组织代码，让职责清晰，而不是性能问题。

顶层函数本质就是静态方法，方法本身不会创建对象。Kotlin推荐大量使用 File + 顶层函数，主要是为了避免无意义 Utils 类，
让代码职责更清晰。真正需要控制的是顶层变量、单例对象、缓存对象，而不是函数数量。

和 Object 的区别

| |顶层函数|object|
|-|-|-|

|生命周期|类加载|对象生命周期|
